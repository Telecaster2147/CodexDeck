# CodexDeck 0.4.0

CodexDeck 0.4.0 is the first beta-quality release candidate. It strengthens the evidence contract,
package structure, protocol validation, published snapshot immutability, diagnosis consistency, and
maintainability while preserving the observer-only product boundary.

## Highlights

- Moved the runtime into the collision-free `codexdeck.*` package namespace; `codexdeck` remains the
  only installed command.
- Expanded the independently adjudicated ground-truth corpus to 50 cases across lifecycle, attention,
  terminal association, observer degradation, stall/silence, discovery, network, and recovery.
- Added a rolling current/previous Codex CLI compatibility fixture window using the production rollout,
  SQLite, replay, state-machine, and terminal paths.
- Structurally freeze every published `MonitorSnapshot` branch. Later samples cannot mutate values
  reachable from older snapshots, while unchanged branches can still be reused by identity.
- Added stable per-axis reason codes and a bounded evidence timeline shared by Diagnosis, text, JSON,
  doctor, and single-session export.
- Split full sampling, rollout reading, state derivation, and TUI navigation into focused stages without
  changing the two-second full-sample or 100 ms rollout-refresh contracts.
- Reorganized public documentation around operator tasks and explicit ownership for architecture,
  evidence, state, protocol compatibility, terminal, network, testing, and release observability.

## Compatibility and schemas

- Core JSON/NDJSON remains `schema_version: 1`.
- Doctor remains `doctor_schema_version: 2`.
- Single-session export remains `export_schema_version: 3`.
- Reason and evidence-timeline fields are additive, bounded, redacted projections.
- Validated fixture minors remain Codex CLI `0.145.x` (current repository window) and `0.144.x`
  (previous repository window); these labels do not claim to track the newest upstream release.

## Upgrade notes

The public command and operator workflows are unchanged. Python imports from the historical flat
runtime layout are no longer part of the installed package; integrations should invoke `codexdeck` or
use the `codexdeck.*` namespace. Existing CodexDeck preference files remain readable.

The project remains read-only: it does not attach to PTYs, write stdin, send signals, change Codex data,
inspect packet payloads, or proxy traffic.
