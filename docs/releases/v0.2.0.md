# CodexDeck 0.2.0

CodexDeck 0.2.0 将工具从多会话状态列表推进为证据驱动的只读运行态控制台。本版本重点提升
快照一致性、会话与终端归属准确性、上游协议兼容能力，以及需要用户处理事项的发现效率。

## 主要新增

- 新增 Attention Queue，统一汇总审批、权限、用户输入、登录等待、当前失败、确认的网络停顿和
  活跃会话观测盲区；TUI 顶部显示待处理数量，并可使用 `]` 快速跳转。
- 新增匿名 rollout replay 框架，通过正式增量 reader、event normalization、状态机和 TerminalStore
  重放协议 fixture，覆盖 partial line、未知 phase、后台 yield/poll 和完成关联。
- 新增有界 incident summary 与 `export --current-incidents`，集中导出当前异常会话的事件、恢复结果、
  provenance 和 evidence，且不包含 terminal transcript 正文。
- history schema 增加 lifecycle、上游等待、attention wait、observer blind 和协议降级持续时间统计。
- 增加本地长期运行基准，覆盖百万级 rollout、terminal 全局保留上限和 24 小时事件 churn。

## 主要修复

- 已发布 snapshot 不再被后续采样原地修改；没有可见变化时继续复用同一对象，有变化时发布新的
  coherent snapshot，避免 TUI 错过刷新或跨采样读取混合状态。
- 引入 instance、session、process、rollout、terminal 和 socket 复合 identity，避免 PID 复用、
  多 Codex Home、重复 call ID 和并行连接造成错误归属。
- long-running background job 的 initial exec 离开 rollout lookback 后，full sample 仍可通过只读进程
  证据恢复 `METADATA_ONLY` terminal，同时排除 CodexDeck observer 子树和内部 Codex 进程。
- rollout normalization 拆分为 attention、compaction、tool、collaboration、response item 和 event
  message handlers；未知上游形状保留统计并在 doctor 中显示 compatibility 状态。
- engine 将 discovery、socket 和 publication 阶段分离，TUI 使用独立 sampling coordinator 管理
  100 ms fast refresh、2 秒 full sample 和单 worker 约束。
- Terminal 页面继续保持只读，明确显示 capability、PID、command、cwd、状态、截断和 dropped bytes。
